## 2024-08-06 - Optimized TelemetryEngine SQLite Connections
**Learning:** Re-opening a new SQLite connection (`sqlite3.connect`) and a file handle (`open("a")`) for every single log event causes massive IO overhead and blocks high-frequency event logging. In `omni_pilot/telemetry.py`, this dropped throughput significantly.
**Action:** Use a persistent SQLite connection and a persistent file handle. Enable `journal_mode=WAL` and `synchronous=NORMAL` on SQLite for massive speedups on write-heavy workloads. Protect both with a `threading.Lock()` to ensure thread safety without losing speed. Do not use `atexit.register(self.close)` for cleanup, as it creates a global reference preventing garbage collection and causes file descriptor leaks. Instead, implement `close()` and hook it into `__del__()` (while ignoring errors if interpreter shutdown is in progress).
